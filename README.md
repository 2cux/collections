# 曹波个人网站

项目已清理为重构起点，保留开场视频和“点击进入”按钮。点击后显示温暖明亮的背景：奶油色底，柔和的桃色、浅金色与浅绿色渐变光晕。背景正中央显示半透明圆角问候卡片，配有用户提供的金发猫耳卡通头像、英文手写字体与青绿色 Cao Bo 名字。问候语按访客本地时间自动切换：05:00–11:59 为 Good Morning，12:00–17:59 为 Good Afternoon，其余时段为 Good Evening；页面保持打开时也会更新。

点击进入时，开场画面轻微放大并渐隐，约 1.2 秒内融入背景；系统启用减少动态效果时使用短暂淡出。

点击问候卡片进入角色界面，背景保持不变。角色素材基于用户提供的原图，经 ImageGen 补齐耳朵、清理外轮廓杂点，再采用 SVG 轮廓裁切分离头部和衣服，绑定独立眼睛；鼠标在页面任意位置移动时，双眼和头部会平滑跟随，并有自动眨眼、轻微呼吸。眼睛的球面投影与转向缩放参考 [Bencho Eye tracker](https://bencho.dev/blocks/magnet-select?c=eye-tracker&theme=dark)。点击返回或按 Escape 回到问候卡片，焦点回到卡片按钮；触摸屏支持点按位置跟随。后台页面和退出界面时停止 JavaScript 动画，系统减少动态效果时关闭转头、呼吸及自动眨眼。

当前实现是网页二维分层动画，不包含 Cubism 的 `.moc3` / `.model3.json` 原生 Live2D 模型。

## 运行

默认以居中的问候卡片为主体，左侧是 Github Activity Heatmap 紧凑入口，显示 `2cux` 今年的真实贡献总数。点击入口后，模块在约 650ms 内展开，并将问候卡片和联系方式平滑推到右侧；点击收起回到居中布局，焦点回到入口。窄屏在问候卡片下方展开，系统减少动态效果时直接切换。奶油米色空白格和四级暖鼠尾草色与原有玻璃卡片、手写标题协调。窄屏放在问候卡片及联系方式下方，日历支持横向滚动并默认显示最近的月份。使用 https://uiarc.dev/r/activity-heatmap.json 提供的原版 React + Motion 组件、CSS Module 与官方 motion tokens（来源记录在 src/components/activity-heatmap/SOURCE.md），保留斜向波浪入场、数字滚动、弹簧滑动提示框、日期选中框、图例高亮筛选以及键盘操作。提供最近三个自然年的独立切换（当前为 2026、2025、2024），默认今年；每年使用对应的完整日历，保留闰年 2 月 29 日，按真实 GitHub 等级确定色阶，并遵循系统减少动态效果设置。仅在模块展开动画完成后挂载日历，避免变形期间的尺寸测量与方格动画开销。展开与收起使用位移、缩放动画，批量读取布局，期间暂停卡片悬停；保留稳定占位与焦点管理。组件主题变量仅作用于活动卡片。

`/api/github/activity?year=2026` 按年份独立缓存最近三年的贡献数据。页面先显示 `public/data/github-activity-YYYY.json` 的真实记录，再请求 Node 服务更新，避免断网时等待空白。成功后每小时检查；失败或收到旧记录时按 1、2、4、5 分钟间隔重试，之后保持 5 分钟。后台页面暂停定时请求，回到前台时补做已到期的检查，网络恢复也会重试。一个年度失败不会阻止其他年度更新，更新保留展开状态、年份与选中日期。展开面板提供“立即同步”；服务端限制强制刷新每个年度最多每分钟一次。

服务端从 GitHub 公开贡献日历读取，无需 Token；网络错误、429 和 5xx 最多尝试两次，每次超时 6 秒。日历无法读取时，再尝试 `raw.githubusercontent.com/2cux/collections/HEAD/public/data/` 的仓库快照。两条网络路径都失败时，从内存、持久缓存、随项目发布的快照中选择同步时间最新的有效记录，明确标记 `stale: true`，不将回退当作同步成功。接口返回 `source`、`lastAttemptAt` 和 `retryAt`，保留原始 `fetchedAt`。成功记录原子写入 `data/github-activity/`，重启后仍可用；可用 `GITHUB_ACTIVITY_DATA_DIR` 指向持久磁盘。失败期间也会重新读取本地快照，因此手动更新或新部署的数据不会被旧内存覆盖。日期必须连续、符合年度长度且无重复，等级、逐日次数和总和均经过验证。

`npm run sync:activity` 手动抓取三个年度和近一年记录，全部解析成功后才替换静态快照，每个请求最多尝试三次。`npm run test:activity` 验证重试、恢复、并发、持久化、数据验证和前端同步策略。纯静态部署只有已发布快照；实时检查需要 Node 服务。仓库快照目前仍需运行脚本并发布更新，尚未启用云端定时写回。公开日历 HTML 结构若变化需更新 `server/activity.js` 的解析器。

重试不能解决持续的 GitHub 网络不可达。使用已有且获授权的 HTTP 代理时，Node.js 24 可在进程启动前设置 `NODE_USE_ENV_PROXY=1`、`HTTPS_PROXY` 和 `NO_PROXY=localhost,127.0.0.1`，使服务和同步脚本走代理；项目不会自动更改系统代理。支持说明见 [Node.js 代理文档](https://nodejs.org/docs/latest-v24.x/api/cli.html#--use-env-proxy)。

主页右下方的浅色玻璃点赞按钮支持磁吸悬停、爱心弹跳和微粒反馈；窄屏移动到联系方式下方。点赞采用累积逻辑：每次点击加 1，同一访客可连续点赞，不提供取消功能。快速点击会排队保存。计数由 Node.js 后端共享，通过 SSE 实时推送，失败时回退并提示重试。

`npm run dev` 和 `npm run preview` 均自动挂载点赞后端。正式运行：先 `npm run build`，再 `npm start`，默认监听 8787 端口；可通过 `PORT`、`HOST` 修改。该进程同时提供静态页面、视频范围请求和点赞接口。

点赞数据默认保存在 `data/likes.json`，重启保留，并兼容之前的访客列表格式，保留已有赞数。生产部署需要 Node.js 22+、单实例进程和持久磁盘；可用 `LIKES_DATA_FILE` 指向持久卷中的文件。纯静态部署不能提供共享点赞。反向代理需允许 `/api/likes/events` 长连接并关闭缓冲。多实例部署需要将文件存储替换为共享数据库和广播服务。

`npm run test:likes` 验证重复点击累加、实时推送、并发、不允许取消、重启持久化和旧数据迁移。

```sh
npm install
npm run dev
npm run build
```

## 文件

- `index.html`：开场视频和按钮。
- `src/main.js`：应用入口。
- `src/intro.js`：视频播放、末帧停留、按钮入场及点击处理。
- `src/character.js`：角色分层图形、眼睛投影、动画与界面切换。
- `src/character-art.js`：修复后的角色轮廓与眼睛位置校准。
- `src/styles.css`：开场样式和页面背景。
- `public/media/`：原有视频与首尾静态帧。

每次打开或刷新都会重新播放视频。播放失败、持续缓冲或系统启用减少动态效果时显示末帧。视频保持完整 16:9 画面，按钮支持鼠标、触摸和键盘。

开发时可通过 `/?intro-state=final` 查看末帧，通过 `window.__intro.replay()` 重播。
